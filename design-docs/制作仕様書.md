# 『みつやと綴る、やさしいタイピング』制作仕様書 v1.0

**ステータス：企画・キャラクター・画面・入力仕様・全10シーン・8エンディングの制作仕様確定。** この資料は実装用の設計書であり、ゲーム本体や完成イラストの制作完了を意味しません。 `scenarios.json` が会話の正本です。

## 0. 作品定義

- ジャンル：3択同時表示・入力による自動選択型タイピング × 分岐ノベル
- 正式タイトル：**みつやと綴る、やさしいタイピング**
- キャッチコピー：**言葉ひとつで、世界の色が変わる。**
- 主人公：宿木みつや。プレイヤー＝訪れ人。恋愛専用作品にはせず、ゆっくり生まれる信頼を描く。
- 1周：10シーン、目安5〜10分。開始時は10/10/10、毎周リセット。実績と解放画像のみ周回をまたいで保存。
- 世界観：「言葉を選ぶこと」「最後まで綴ること」に意味がある。タイピングのミスでみつやの感情は下がらない。
- モチーフ：夜景、雨、雨傘、本、電車、猫、川面、室内灯、夜明け。

## 2. 画面デザイン仕様書

### 2-1. レイアウト

1. **タイトル**：雨窓のキービジュアル、ゲーム開始／続きから／ギャラリー／遊び方／設定。
2. **会話**：上段に章番号・進捗、中央にみつやのビジュアルと吹き出し、下段に**3候補常時表示**、一番下に「現在入力中」の共通ローマ字表示と残文字。
3. **結果**：到達した結末、みつやの一言、クリアしたタイピング統計、獲得した画像、もう一度、ギャラリーへ。
4. **ギャラリー**：全8結末のサムネイル（未解放はぼかし・シルエット）、達成条件のやわらかいヒント、鑑賞・端末保存。

PC：ゲーム領域最大幅960px、人物と会話を左右構成、候補は3段縦積み（長文の視認性優先）。スマホ：幅100%、立ち絵を高さ30〜35vh程度、候補は縦積み3段、キーボード表示中も候補と進捗が見えるよう折り返し・スクロールを調整。ランドスケープでは横並びも可。候補は日本語漢字文＋ひらがな読み＋進捗付きローマ字を表示。装飾背景と本文のコントラストはWCAG AA相当を目標。

### 2-2. 5テーマ（コード上のtokens）

| テーマID | 状態 | 背景 | UIパネル | 文字 | 強調 | 背景・動き |
|---|---|---|---|---|---|---|
| `normal` | 静かな日常 | `#E9EEE7` | `#F7F8F3` | `#354C43` | `#819B87` | 木漏れ日、細い葉影、緩い光 |
| `warm` | 安心 | `#E9E4D7` | `#FAF4E9` | `#615344` | `#BA9675` | 琥珀の室内灯、ふわりと動く光 |
| `resonance` | 共鳴 | `#1F3C42` | `#2B4A50` | `#EFF6F1` | `#9BD7C8` | 雨上がりの夜景、小さな光点 |
| `uneasy` | すれ違い | `#202832` | `#303842` | `#DAE0E2` | `#8C9CAD` | 暗い青灰、低コントラスト斜線、雨筋 |
| `closed` | 心を閉じる | `#111921` | `#1C252D` | `#D2DCE2` | `#8EACBC` | ライン停止、光源減少、大きな余白 |

**不穏のライン背景**：`repeating-linear-gradient(115deg, transparent 0 22px, rgba(185,205,220,.07) 23px 24px)` をベース背景にオーバーレイ。2層目の縦雨筋は最大透明度0.1、ゆっくり20〜35秒で移動。強いノイズ・点滅・画面シェイクは使わない。通常と不穏の遷移は900ms、色と光を先に変え、人物は穏やかなクロスフェード。`prefers-reduced-motion` では動きを停止し色だけ切替。

### 2-3. 感情と背景の連動

- 会話ID 01〜03 は `normal`、04〜06 は `twilight`（実装では基本 `normal` と `warm` の中間トーン）。07〜10 は `variable`。
- 次の描画テーマは **入力完了後に確定した選択肢の影響を反映したあと** 決める。
- `safety <= 9` または `mask + pressure >= 3` なら `uneasy` を優先。`safety <= 5` なら `closed` を優先（ただし最終結末までは演出のみ、途中終了しない）。
- それ以外で `resonance >= 22` は `resonance`、`safety >= 20` は `warm`、残りは場面の基本色。
- 悪化したテーマから回復可能。回復演出で照明が徐々に戻り、人物の表情も `uneasy → thoughtful → softened` と移行する。
- 数値のゲージは初期状態では非表示。設定で「関係性ヒント」をONにすると、具体的な数値ではなく「すこし心がほどけた」等を表示。エンディング時は数値を公開可。

### 2-4. タイポグラフィ・音・安全性

本文は読みやすい日本語ゴシック、見出しには細めの明朝系をアクセント。UI推奨基本16px、選択肢16〜18px、本文行間1.7以上。夜背景では文字と背景を明確に分離。BGMは雨音・ページをめくる音・控えめなピアノ、音声は初回操作後に再生、デフォルト音量は控えめ、ミュート可能。キー操作と画面タップの両対応。タイピングを間違えてもみつやが責める表現は禁止。暗い展開に入っても激しい明滅なし、モーション軽減設定を提供。

## 3. 入力仕様書 — 3択同時入力／自動選択

### 3-1. 確定挙動

- プレイヤーがクリックで選ばなくても**いきなりローマ字入力**を始められる。3候補それぞれに日本語・読み・ローマ字の進捗を同時表示。
- 入力文字列が各候補の**許可ローマ字表記の接頭辞**に一致するか常に計算。一致が複数なら仮選択状態を維持し、ひとつに絞れればその候補を強調する。
- **1候補になった時点でロックしない**。まだ入力途中なら Backspace で戻せて、別候補へ乗り換えられる。確定は候補全体を完打した瞬間だけ。
- 0候補になる誤入力は受理せずミス回数を+1。既に打った正しい文字列は保持し、穏やかな色変化で通知。
- 1候補が完了したらその返答を確定し、みつやの応答、パラメータ変動、背景転換、次の章へ遷移。選択確定後は追加入力を無視する（連続確定防止）。
- Enterでメッセージを送る方式ではない。タイピング終了＝送信。マウス選択も必要ない。
- 漢字変換を伴う日本語IME入力ではなく**ゲーム専用のローマ字直接入力**。IME変換中（composition）は入力判定しない。スマホでは画面内ローマ字キーボードを提供するか、英字キーボードを明示案内。

### 3-2. ローマ字表記揺れ

`し=si/shi`、`ち=ti/chi`、`つ=tu/tsu`、`ふ=hu/fu`、`じ=zi/ji`、`しゃ=sya/sha`、`ちゃ=tya/cha`、`じゃ=zya/ja`、`っ`は次の子音の重ね打ち（条件あり）、`ん`は `nn` と適切な箇所の `n` など。長音は「う」「お」等の**収録した読み**に従い、読みを勝手に変換しない。句読点、空白、カギ括弧は打鍵対象外。ゲーム用正規化によって読点は表示だけ残す。

**実装方法**：読みを仮名単位に分割し、それぞれのローマ字表記を状態遷移として持つ **トライ木（Trie）／有限オートマトン** を3候補分並行走査。すべての表記組合せを巨大な文字列配列に展開しない。1文字ごとに各候補の「生存状態」を更新。`n` と `nn`、促音や拗音の曖昧さも状態集合で吸収。

例：候補 A `だいじょうぶ`、B `だいじだよ`、C `だまって` のとき、`da` では3件が残り、`dai` でA/Bが残り、`daij` 以降で候補が絞られる（`ji/zi` どちらも認識）。同じ入力で途中まで2候補残るのは正常。

### 3-3. 判定擬似コード

```ts
onKey(char) {
  if (composing || phase !== 'typing') return;
  if (char === 'Backspace') {
    typed = typed.slice(0, -1);
    recomputeCandidates(typed);
    return;
  }
  if (!/^[a-z]$/i.test(char)) return;
  const next = typed + char.toLowerCase();
  const alive = choices.filter(c => c.romanAutomaton.acceptsPrefix(next));
  if (!alive.length) { mistakes++; showSoftError(); return; }
  typed = next;
  updateCandidateHighlights(alive);
  const finished = alive.find(c => c.romanAutomaton.acceptsComplete(typed));
  if (finished) { phase='responding'; commitOnce(finished); }
}
```

**注意**：同じローマ字全文になる選択肢は禁止。文字数だけでなく、正規化後の仮名読みが重複しないことをデータ検証する。誤打・途中修正・表記揺れは関係パラメータに影響させない。

### 3-4. スコアと操作

`accuracy = validKeyCount / (validKeyCount + mistakes) * 100`、`WPM = validKeyCount / 5 / typingMinutes`（ローマ字ベースの目安と明記）。タイムアタックは任意で、基本モードにはタイムアウトなし。コンボはミスなし継続打鍵で加算、章完了時に集計。進行状況・解放イラストは `localStorage` に保存。ゲーム途中の保存も必要ならシーン境界単位。音・動き・画面サイズを設定で調整。プライベートモードやキャッシュ削除で保存データが消える可能性を明記。

## 4. シナリオ — 10シーン×各3択、全30回答

**データの意味**：好感度を単純な正誤にしないため、`親密度(closeness)`、`安心度(safety)`、`共鳴度(resonance)` を使う。初期値はいずれも10、上下限は0〜40。`insight`＝相手のペースや気持ちを尊重した選択、`mask`＝本音の軽視、`pressure`＝返答を迫る選択。これらは展開のための物語フラグであり、プレイヤー個人の性格診断を意図しない。全シーンは共通で通過し、みつやの表情・背景・結末が選択の累積で分岐する。後日、章内の分岐セリフ差し替えは拡張可能。

**表示文と入力文の分離**：画面には漢字付きの美しい会話文を表示。打鍵用には `reading` を使う。読みは執筆時点の確定値であり、自動ふりがな変換による表記揺れを避ける。

## 5. エンディング設計（8種類）

**条件は上から優先判定**。章10の選択確定後に決定。`total` は3数値の和。条件が同時成立する場合は上位を採用。**一度の入力ミスではエンドは変わらない**。エンディングはバッドでも回収可能な特別画像を与え、ギャラリーに残す。

| 優先 | ID | 結末 | 判定条件 | ごほうび | みつやのラストワード |
|---|---|---|---|---|---|
| 1 | `BAD_03` | 届かなかった言葉 | `pressure >= 3` | 街灯の下、誰もいない橋 | 「話せないことまで、急いで渡さなくてよかったんだ。」 |
| 2 | `BAD_02` | 優しさの仮面 | `mask >= 3` | ガラスに映る曖昧な笑顔 | 「大丈夫、って言いすぎたのかもしれない。」 |
| 3 | `BAD_01` | 閉じた窓 | `safety <= 5 or resonance <= 5` | 灯りの消えた窓辺 | 「……今夜は、ここまでにしよう。」 |
| 4 | `SECRET` | 雨のあとに残る星 | `insight >= 7 and total >= 75 and safety >= 22 and pressure < 3 and mask < 3` | 特別な夜明けとみつやの横顔 | 「言葉が違っても、同じ空を見られるんだね。」 |
| 5 | `HAPPY_RESONANCE` | 星を分けあう夜 | `resonance >= 26 and total >= 60` | 星明かりの川辺 | 「考え方が重なる瞬間って、静かなんだね。」 |
| 6 | `HAPPY_SAFETY` | 雨音の居場所 | `safety >= 26 and total >= 60` | 猫と灯りのある部屋 | 「ここでは、何も急がなくていいんだね。」 |
| 7 | `HAPPY_CLOSENESS` | 夜明けの約束 | `closeness >= 24 and total >= 60` | 朝焼けを眺めるみつや | 「また会えたら、続きを聞かせて。」 |
| 8 | `NORMAL` | また会うための余白 | `otherwise` | 雨上がりの書店の栞 | 「今日の話は、ここに置いておこう。」 |

**バッドエンドの演出**：`BAD_03` は夜の橋で足音が遠ざかる、`BAD_02` は笑顔だけ残して室内灯が暗くなる、`BAD_01` は窓辺が静まり光が消える。どの結末にも、責める言葉・自傷や絶望を肯定する演出を入れない。再挑戦画面には「別の言葉でもう一度話す」を提示。**シークレット**では窓の向こうの夜景から夜明けへ変化し、特別な一枚を解放する。

**周回設計**：初回クリアでギャラリー解放、各結末につき1枚ずつ収録（計8枚）。全8枚獲得で額装フレーム装飾の追加アンロック（新規9枚目は初版に含めない）。未解放画像は題名を「？？？」、ヒントは「急がずに耳を傾けると……」等。画像はゲームプレイ中のシーン画像と別の高品質一枚絵で制作する。

## 6. 品質検証・開発への引き渡し条件

- `scenarios.json` は全10話×各3択＝30件で、すべて日本語文・読み・みつやの返信・数値変化・フラグ・遷移先を必須項目に持つ。
- 3択の読み重複なし／入力全完了でのみ回答確定／1文字誤入力で章が進まない／Backspaceで未確定候補を復活可能。
- `shi/si` 等の揺れ、`っ`、`ん`、拗音、ひらがな全文を含む入力テストを作る。
- 全8結末は**少なくとも1つの選択系列で到達可能**なことを全 `3^10=59,049` パターンで検証する（結果は `verification.txt`）。
- PCとスマホで候補3件が読めること、タッチ操作、通常キーボード、IME合成中操作、モーション軽減の確認。
- 著作権・プライバシー・ギャラリー画像のダウンロード可否を公開前に確認。素材を含むファイルと、プログラムソースをGitHub Pagesで公開できる形式に分離。
